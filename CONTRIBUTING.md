# Contributing

Thank you for taking the time to contribute.

## Before opening an issue

Please search existing issues first. When reporting a bug, include the expected behaviour, the actual behaviour, reproduction steps, environment details, and screenshots or recordings when the issue is visual.

## Before opening a pull request

Please keep each pull request focused on one user-facing improvement. Explain the problem, describe the approach, and call out any trade-offs or follow-up work. Do not include credentials, private data, generated build output, or unrelated formatting changes.

## Local checks

Run the repository's documented installation and verification commands before opening a pull request. For frontend changes, include responsive checks and note any accessibility or reduced-motion considerations.

## Review standard

Contributions are evaluated for clarity, maintainability, responsive behaviour, accessibility, privacy, and alignment with the project's product direction. Constructive discussion is welcome; please keep feedback specific and respectful.
